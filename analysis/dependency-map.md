## 2. Dependency types

| Edge | Type | Note |
|---|---|---|
| S02 → D09 | Mathematical (deterministic) | sum over weekly events of τ; correctness checkable |
| T05 → D10 | Stochastic | wait ~ U(0, headway) is an *assumption* (random arrival); students who time arrivals wait less |
| H09 building age → H10 utilities | Correlational, not causal per se | older envelope ⇒ more heat loss is physically plausible, but unit-level data rarely available → treat as wide interval |
| S11 value of time → ranking | Mathematical, **dominant** | Single scalar flips rankings between cheap-far and pricey-close; must be surfaced & swept |
| H21 reviews → risk | Informational, selection-biased | extreme-experience bias; use shrinkage, never as hard fact |
| M02/M03 market timing | Weak data | blocks rigorous optimal-stopping model |
| S13 budgets ↔ S14 valuations | Strategic | roommates can misreport valuations; envy-free LP is not strategy-proof (known result) |
| TE3 LLM in path → HK3 external services | Operational | each external dependency multiplies demo failure risk |

## 3. Which parameters most influence the *product selection* (screening sensitivity)

Ranked by (sensitivity H) × (spans many concepts) × (availability):

1. **S02 weekly schedule** — 13 high-sensitivity parameters cluster in the SCHED family; it is the one input that makes the decision "identity-based" (routine, not demographics) and is cheap to collect.
2. **S11 value of time** — the coupling between time and money; drives the core trade-off. Unknown to students ⇒ natural target for elicitation / sensitivity sweep.
3. **H08/H10 utilities & fees** — large, hidden, seasonal; data obtainable from public rate sheets + assumptions.
4. **S13–S15 group inputs** — high value (9 H-sensitivity params) but each extra roommate multiplies onboarding friction.
5. **S27 latent weights** — unknown by construction ⇒ either elicit (PREF) or integrate over (ROBUST/SMAA).
6. **H19 availability / DA2 coverage** — volatile and unknowable without listing API ⇒ pushes toward a tool that *evaluates* listings the student brings (paste/link) or a curated, dated, labeled sample, rather than a search engine.
7. **T03 GTFS validity** — hard prerequisite for credible bus times; if UM Blue Bus GTFS unavailable, fall back to published headways (documented assumption).

## 4. What the parameterization reveals

- **The SCHED × TCO coupling (through S11) is the structural center of the problem.** Existing listing filters treat location as a static distance to one point; the matrix shows the decision really depends on *many destinations × times × modes × seasons*.
- **Most housing-side parameters (H07, H08, H10, H25) are "listed-but-hidden"** — present in lease text, not in filter UIs. That is a structured-extraction opportunity (AI role) whose output feeds deterministic math.
- **Market-timing parameters (M02, M03) are low-confidence** ⇒ a "sign-now-vs-wait" optimal stopping model would rest on fabricated curves. Deprioritize.
- **Preference weights are unknowable upfront** ⇒ any single-number score is fragile; robustness measures (D03/D04) are cheap to compute and directly address rubric "uncertainty".
- **Privacy**: only S06/S32 (mobility/accessibility) are sensitive; make optional and never inferred. No demographic parameter is needed for any concept family.

## 5. Sensitivity-based design-space reduction

Families ordered by (high-sensitivity params × data availability ÷ friction):
SCHED (high, data available via OSM/GTFS) > TCO (high, public rate data) > ROBUST (computed, no new data) > GROUP (high value, higher friction) > PREF (computed, adds interaction) > FIT/extraction (AI-dependent) > TIMING (data-starved).

These rankings are a **research-supported inference from the matrix**, not an empirical result. They are revisited after agent reports and interviews.
